# 50件の意味的類似テスト用タイムライン

`x-timeline-50-semantic-cases.json` は、`pakulist` が直接読み込める X API v2 Search形式の完全な架空データです。10アカウント・50投稿で構成され、完全一致、文字列近似、意味理解を必要とする言い換え、および意味が異なる近似文を同時に検証できます。

| シナリオ | 投稿ID | 期待する扱い |
|---|---|---|
| 完全一致 | 001–007 | 本文、URL除外後、メンション除外後の完全一致です。外部APIへ送信しません。 |
| 単純な文字列近似 | 008–017 | 語順、表記、助詞などが近い投稿です。既定閾値0.80では3組が候補になります。 |
| 語彙が近い意味的言い換え | 018–029、049–050 | 言い換え・場所変更・延期・営業時間の説明を含みます。049–050は近似度0.78であり、閾値0.70で候補化します。 |
| 意味が異なる近似文 | 030–037 | 否定、条件、対象範囲により意味が異なります。030–031は近似度0.80で候補化しますが、意味的判定では `non_match` が期待されます。 |
| LLM必須の意味的言い換え | 038–045 | 連続する各2投稿が、同じ事実をほぼ異なる語彙で表します。文字列Jaccard類似度は0.00–0.09であり、最小閾値0.50にも達しません。意味検索・埋め込み検索・LLMによる候補生成が必要です。 |
| 非一致対照 | 046–048 | 一致候補に含まれない独立した投稿です。 |

## 実行方法

最初にJSONを選択して読み込みます。完全一致と文字列近似だけを確認する場合は、既定の近似一致閾値 **0.80** のまま検出します。この設定では完全一致3クラスタと近似一致4クラスタが表示されます。

意味理解が必要な登録条件の言い換え（投稿049–050）もOrcaRouterに確認させるには、近似一致の閾値を **0.70** に下げてから、**「OrcaRouterで意味的類似を確認する」** を有効にします。完全一致クラスタはこの操作をしても外部APIの送信対象にはなりません。

> 投稿038–045は、現在の`pakulist`の「文字列近似で候補を作ってからLLMで判定する」構成では、LLMに送られる前の候補化段階で取りこぼされます。これらを自動的に検出するには、候補生成段階に意味検索・埋め込み検索・LLMを追加する必要があります。

> 投稿030–031は文字列上かなり似ていますが、一方は公開予定を示し、もう一方は公開しないことを示します。このペアは文字列近似だけでは同一視しないよう、意味的類似APIの `non_match` 判定を確認する用途です。
