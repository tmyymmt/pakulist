# pakulist ハッカソン想定質疑応答（3分）

## 使い方

質疑応答は3分である。以下は全問に答える台本ではなく、質問ごとに**20〜30秒で結論、根拠、次の検証**の順に答えるためのカードである。未実装の機能を実装済みと説明せず、現行MVPの無保存・ローカル処理の境界を守る。

| 想定質問 | 20〜30秒の回答 | 根拠・補足 |
| --- | --- | --- |
| **なぜ完成品まで作らなかったのですか。** | 主ユースケースには、投稿データを正規に扱えるか、誰が価値を感じるか、AI原価が成立するかという前提があります。そこを未確定のまま自動取得・保存・AIを作り込むと、安全性も事業性も検証できません。今回は計画を主に作り、その境界を確かめる最小プロトタイプに絞りました。 | 外部データ連携の承認、利用者検証、実AI評価を段階的に進める計画がある。 |
| **既存のSNS検索や監視ツールと何が違いますか。** | pakulistの焦点は、候補を見つけることだけではなく、人が確認できる根拠へ整理することです。URL、投稿時刻、本文、類似度、判定種別を同じ出力へまとめ、最終判断は人に残します。差別化は、判断の自動化ではなく、判断可能な状態の再現性です。 | 現行MVPはCSV/HTML出力と注意事項を提供する。 |
| **AIを使わないなら、AIプロダクトではないのでは。** | 現在のMVPでは、AIを使わない決定的手法を基準線にしています。AIの役割は言い換え・部分改変の取りこぼしを補うことですが、精度、偽陽性、棄権、原価を測れない段階で有効化しません。AIを使う必然性を評価可能な形に分離したことが、次のAI検証の前提です。 | 実AI評価は、モデル・単価・データ権限が確定した限定条件で行う。 |
| **投稿データやプライバシーは安全ですか。** | 現行MVPは利用者のローカルファイルをブラウザ内で処理し、サーバー保存、外部API、自動通報を行いません。将来の外部連携については、最小化、保持期限、削除、資格情報、監査、アクセス制御を実装前の必須ゲートにしています。 | 現状の安全性と将来サービスの安全性を混同しない。 |
| **誰が、何にお金を払うのですか。** | 仮説上は、重複候補の確認・証拠整理を反復するブランド保護やマーケティング運用担当です。ただし価格は未確定です。OSSの決定的検出は無償に保ち、変動原価が生じる意味的類似判定を有料候補として、利用者価値・頻度・原価をヒアリングと実測で検証します。 | 価格を先に確定せず、利用者検証と料金設計をP1としている。 |
| **誤検知によって不当な通報につながりませんか。** | 候補は結論ではありません。出力には判定方式と注意事項を含め、利用者が原投稿・公開状況・規約を確認して最終判断する設計です。自動通報や人物・組織関係の断定は行いません。今後のAI評価でも偽陽性と棄権を必須指標にします。 | 「候補」「人の最終判断」「自動通報しない」を一貫して答える。 |
| **関係性グラフは監視や人物追跡になりませんか。** | 現時点ではグラフは論理設計だけで、UIも保存サービスもありません。将来も、本文を返さない最小API、根拠件数・期間での集計、保存・削除・権限のゲートを前提にします。利用者価値と適切なデータ権限が確認できるまで実装しません。 | 関係性の断定ではなく、検出根拠の集計として扱う。 |
| **次の3か月で何をしますか。** | 第一に正規な外部データ連携の承認・運用条件を確定します。第二に利用者検証で課題、価格、利用枠、グラフ価値を測ります。第三に、単価と権限が揃った場合だけAIを限定評価します。機能数より、承認と実測を成功条件にします。 | 現在の優先順位は評価基準の「次に進める順序」と一致する。 |

## 回答上の禁止事項

| 避ける表現 | 置き換える表現 |
| --- | --- |
| 「違法投稿を検出します」 | 「重複・類似投稿の候補と根拠を整理します」 |
| 「AIが判定します」 | 「将来のAI評価で、候補の精度・偽陽性・棄権・原価を測定します」 |
| 「安全です」 | 「現行MVPは無保存・ブラウザ内処理であり、将来連携は別の安全要件を実装してから開始します」 |
| 「完成しています」 | 「計画主導の最小プロトタイプで、未達事項と次の検証を明示しています」 |
