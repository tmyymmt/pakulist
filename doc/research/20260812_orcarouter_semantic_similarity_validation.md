# OrcaRouterを用いる意味的類似判定の調査記録

## 1. 結論

有料AIによる意味的類似判定は、OSSの決定的検出エンジンから分離した後続サービスで提供する。OrcaRouterはOpenAI互換のゲートウェイとして、`https://api.orcarouter.ai/v1`をベースURLに設定して利用できる。実際のAPI呼び出しには利用者が提供し、安全なサーバー側シークレットストアで管理するAPIキーが必要である。[1] [2]

現セッションにはOrcaRouterコネクタおよび利用者提供のAPIキーがない。このため、本Issueでは実API呼び出し、モデル精度の実測、実モデル単価の確定、APIキー設定を行わない。代わりに、評価セット、比較指標、API境界、障害時の失敗方針、結果スキーマ、原価計算式を定義する。

## 2. 公式API上の前提

| 項目 | 設計上の扱い |
| --- | --- |
| API形状 | OpenAI互換の`POST /v1/chat/completions`を採用し、将来サービス層だけが呼び出す。[1] |
| 認証 | Bearer APIキーを必須とし、クライアント・OSS・リポジトリ・ログ・エクスポートへ露出しない。[1] |
| モデル指定 | provider-prefixed model IDを明示指定する。`orcarouter/auto`は評価再現性を下げるため、定常評価では使わない。[1] |
| フォールバック | `extra_body.models`と`route: fallback`を、可用性対策に限定して使う。実際に解決したモデル・フォールバック段階・使用量を記録する。[1] |
| エラー | 401、402、429、502では候補判定を成功扱いにせず、決定的手法の結果へフォールバックして「AI判定未実行」を返す。[1] |
| 料金 | OrcaRouter自身のルーティング手数料は0とされるが、上流プロバイダーのトークン料金と任意プラン料金は別に確認する必要がある。[2] |

## 3. データ取り扱いの制約

実評価は、最初は架空または権限を確認済みの最小化済みテキストだけを使用する。外部X API由来のContentを送る場合は、`external_data_governance.md`の利用目的・データソース・設計・運用ゲートを満たすことが前提である。本文、URL、アカウント、トークンを監査ログに残さない。[3]

AI判定の結果は「意味的類似の候補」であり、権利侵害、投稿者の属性、共同運用、不正行為その他の結論を出力しない。事案ごとの利用者確認と手動通報の原則を維持する。

## 4. 原価計算式

モデルごとの最新単価を運用開始直前に公式のモデル価格表から設定し、固定値をソースコードへ埋め込まない。1判定の変動原価は次式で計算する。

```text
costPerJudgment = (inputTokens / 1,000,000 × inputPricePerMToken)
                + (outputTokens / 1,000,000 × outputPricePerMToken)
                + routerSurcharge
```

月額予測は`costPerJudgment × monthlyJudgments + subscriptionFee`とする。キャッシュ、リトライ、フォールバックを別の係数で見積もり、予算上限の80%で警告、100%でAI判定キューを停止する。ルーターの料金表・上流モデルの料金・利用量・為替・税は変動するため、実運用前に再確認する。[2] [3]

## 5. 実装開始前のゲート

1. OrcaRouter APIキーを利用者が安全に提供し、サーバー側シークレットストアで利用できること。
2. モデル名、入力・出力単価、月額サブスクリプション、予算上限を確定すること。
3. 評価セットのデータ権限と利用目的を確認すること。
4. 評価結果が、決定的手法を上回るか、または許容できる誤検知率に収まること。
5. 認証・監査・削除・再配布・障害時フォールバックを統合テストすること。
