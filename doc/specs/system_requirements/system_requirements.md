# システム要件

`doc/specs/business_requirements/goal_and_usecases.md` のゴール・ユースケースを実現するためのシステム要件を定義する。
本ファイルは「何を満たす必要があるか」までを対象とし、実現手段（方式）は `doc/specs/architecture_design/` に記載する。

## 1. 対象SNS

- 最初に対応する SNS は **X（旧 Twitter）** とする
- 他 SNS への対応は将来拡張とし、SNS 依存部分を差し替え可能な構造にする（方式設計で担保する）

## 2. 提供形態の要件

### 2.1 ベース部分（OSS）

| ID | 要件 |
| --- | --- |
| SR-B01 | GitHub 上で OSS として公開する |
| SR-B02 | ライセンスは Apache License 2.0 とする（リポジトリ直下の `LICENSE` を正とする） |
| SR-B03 | ベース部分単体で、同一投稿の検出とリスト化が完結すること（有料サービスなしで動作する） |
| SR-B04 | 有料サービス部分から利用される前提のため、拡張点（インターフェース）を定義すること |
| SR-B05 | 利用者が明示的に有効化したローカル試作として、固定モデルを用いるOrcaRouter意味的判定を実行できること。完全一致は外部送信しないこと。 |
| SR-B06 | LLMの`match`を最終近似一致へ追加し、LLMの`non_match`を文字列近似候補から除外できること。未確認・棄権・利用不可の文字列近似候補は維持すること。 |

### 2.2 有料サービス部分（クローズド）

| ID | 要件 |
| --- | --- |
| SR-P01 | 有料サービスはベース部分（OSS）を前提として動作する |
| SR-P02 | 有料サービス部分のソースコードは非公開（クローズド）とする |
| SR-P03 | 利用者認証、保存、課金、利用枠、承認済みX API取得を伴うAI機能は有料サービスで提供する |
| SR-P04 | AI 利用時の LLM 呼び出しは **OrcaRouter** を経由する |

補足: OSSには、利用者が自らのAPIキーを一時的なローカル環境変数で与える試作的な意味的判定が含まれる。これは認証、保存、課金、利用枠、投稿取得を提供せず、完全一致を送信しない。管理されたAI利用とX API取得は有料サービスの対象とする。

## 3. 検出機能の要件

| ID | 要件 |
| --- | --- |
| SR-D01 | 同一文面の投稿を複数アカウントから検出できること |
| SR-D02 | 検出結果をアカウント単位のリストとして出力できること |
| SR-D03 | リストには通報に必要な情報（アカウント識別子、投稿URL、投稿日時、投稿本文）を含めること |
| SR-D04 | ローカル試作では、文字列近似候補と時系列近傍の発見候補をOrcaRouterで意味的に判定し、最終近似一致へ追加・除外できること |
| SR-D06 | 認証、保存、課金、利用枠又はX API取得を伴う管理型AI機能を有料サービスとして提供できること |
| SR-D05 | 将来拡張として、アカウント間の関係性を可視化できる形でデータを保持すること |

## 4. SNS 規約遵守・BAN 回避の要件

本システムは SNS の利用規約に違反せず、利用アカウントが凍結（BAN）されない手法のみを用いる。

| ID | 要件 |
| --- | --- |
| SR-C01 | 投稿データの取得は SNS の規約・開発者利用条件に従った手段のみを用いる |
| SR-C02 | レート制限を遵守し、過剰なリクエストを行わない |
| SR-C03 | 自動通報（通報操作の自動化）は行わない。通報は利用者の操作を起点とする |
| SR-C04 | 検出・通報のための複数アカウント運用など、規約違反となる回避手段を用いない |
| SR-C05 | 取得データの保持範囲・保持期間を定め、規約上許容される範囲に限定する |

前提となる規約の調査結果は `doc/research/20260811_x_rules_on_duplicate_posts.md` を参照。異なる複数アカウントの投稿を取得・利用する後続フェーズでは、`doc/specs/system_requirements/x_data_acquisition_policy.md` を正とし、保持・削除・再配布・資格情報・監査の具体要件は `doc/specs/system_requirements/external_data_governance.md` を正とする。現行MVPは外部取得を行わず、利用者が正規に取得済みのローカルファイルだけを扱う。
