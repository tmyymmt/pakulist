# X投稿データ取得・利用ポリシー

## 1. 目的

本書は、pakulistが異なる複数アカウントの重複投稿を検出するために必要な投稿データを、Xの規約・開発者条件に沿って取得・利用するための要件を定義する。対象は現行のローカルOSS MVPではなく、X APIまたはX Contentを利用する後続フェーズである。

> **決定**: 利用者自身のXアーカイブだけでは、原則として異なる複数アカウントの比較に必要なデータを満たさない。pakulistが他アカウント投稿を取得する機能を提供する場合は、Xの公式APIだけを利用し、書面による許可、利用目的の承認、データ管理方針、実装上の保護策を先に満たす。

## 2. スコープ

| 区分 | 方針 |
| --- | --- |
| 現行OSS MVP | 利用者が正規に取得済みのCSV/JSONをローカルで選択する。外部API、認証、取得、保存、通報操作は行わない。 |
| 後続の取得機能 | X APIを使うオンデマンド取得だけを検討する。利用者が指定した期間・検索条件・対象アカウントに限定する。 |
| 対象外 | スクレイピング、ブラウザ自動操作、トークンのクライアント露出、無差別・継続的な監視、自動通報、無許可の再配布。 |

## 3. データ取得要件

| ID | 要件 |
| --- | --- |
| DAR-01 | 他アカウント投稿の取得は、Xが提供する公式APIを通じてだけ行う。画面スクレイピング、ブラウザ自動操作、非公式APIは利用しない。 |
| DAR-02 | APIによる取得・分析・表示機能を公開する前に、Xへ利用目的を正確に開示し、Developer Policy上必要な書面許可を取得する。承認された利用目的を実質的に変更する場合も、必要な通知・承認を行う。 |
| DAR-03 | API資格情報はサーバー側の秘密情報としてだけ管理し、ブラウザ、ローカル入力ファイル、ソースコード、ログ、エクスポートへ含めない。 |
| DAR-04 | 最初の取得機能は、利用者が明示した検索条件に対する一回限りのオンデマンド検索に限定する。Filtered Stream、定期実行、全量収集は別途の要件・承認なしに実装しない。 |
| DAR-05 | Recent Searchを使う場合は過去7日間という期間制約をUI・仕様・結果に明示する。全履歴が必要な場合は、Full-Archive Searchのアクセス条件、費用、許可、必要性を再評価する。 |
| DAR-06 | レート制限を監視し、`x-rate-limit-*`応答ヘッダー、429、バックオフ、予算上限、停止条件を実装する。制限の回避や複数アプリによる迂回を行わない。 |
| DAR-07 | 取得対象は、事案に必要なアカウント、期間、検索語に最小化する。サービスは、特定の違反を断定せず、重複投稿の候補整理を目的として動作する。 |
| DAR-08 | API取得Postを表示・保存する場合は、削除・保護化・利用不能化に追従する。Xまたは対象アカウントから削除要求を受けた場合の24時間以内の対応を含め、保持・削除を設計する。 |
| DAR-09 | API取得X Contentを第三者へ出力・再配布する場合は、Post ID・URLを既定とし、本文等のPost Objectを含む出力はXの件数・方法・許可条件を確認したうえで制限する。 |
| DAR-10 | API取得データの保持期間、削除、監査、アクセス制御、障害・漏えい対応は、実装前に`#9`で確定する。 |

## 4. 採用する段階的導入

| 段階 | 内容 | 着手条件 |
| --- | --- | --- |
| 0: 現行MVP | 正規取得済みローカルファイルの検出だけを行う。 | 既存実装の範囲内。 |
| 1: 方針・許可 | 利用目的、APIアクセス、費用、Developer Policy上の必要な書面許可、データ管理を確定する。 | 本書、#2、#9の完了。 |
| 2: 入力アダプター | 採用済みデータソースを標準`Post`形式へ変換する。 | #3の完了。 |
| 3: オンデマンド取得 | 利用者指定の期間・検索条件でRecent Searchを実装する。 | 段階1〜2、秘密情報管理、レート制御、削除対応、利用者検証の完了。 |
| 4: 拡張判断 | Full-Archive Search、継続監視、関係性可視化などの必要性を再評価する。 | 価値検証、費用、規約、保持方式が確定していること。 |

## 5. 現行MVPへの影響

本ポリシーは、現行MVPにX API機能を追加するものではない。現行MVPは引き続き、正規取得済みのローカルCSV/JSONのみをブラウザ内で処理する。利用者自身のアーカイブを含む単一アカウントだけの入力では、異なるアカウント間の重複クラスタが検出されない可能性があることを、利用案内で明確にする。
