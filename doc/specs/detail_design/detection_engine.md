# 詳細設計: 決定的重複投稿検出エンジン

## 1. データモデル

```js
/** @typedef {{ id: string, account: string, url: string, postedAt: string, text: string }} Post */
/** @typedef {{ id: string, matchType: 'exact'|'approximate', similarity: number, posts: Post[], accountCount: number, postCount: number }} DetectionCluster */
/** @typedef {{ approximate: boolean, threshold: number, ignoreUrls: boolean, ignoreMentions: boolean }} DetectionOptions */
```

入力投稿は検証後に空白を除去した`id`・`account`・`url`・`postedAt`・`text`を持つ。画面表示用の原文`text`は保持し、判定用の正規化結果は内部だけで使う。クラスタIDは実行ごとに`C-001`から連番で発行し、永続化しない。

## 2. 公開関数

| 関数 | 入力 | 出力 | 例外・エラー |
| --- | --- | --- | --- |
| `parseInput` | ファイル本文、拡張子 | 投稿配列 | CSV/JSON形式エラー |
| `validatePosts` | 投稿配列 | 検証済み投稿配列 | 必須値・URL・日時・重複ID・上限エラー |
| `normalizeText` | 本文、設定 | 正規化文字列 | なし |
| `jaccardSimilarity` | 2つの正規化文字列 | `0`〜`1` | なし |
| `findDuplicateClusters` | 投稿配列、設定 | クラスタ配列 | 設定値エラー |
| `clustersToCsv` | クラスタ配列 | CSV文字列 | なし |

## 3. 入力検証の手順

1. JSONは配列または`posts`配列を受理する。CSVはヘッダ行を必須とする。
2. 解析直後に最大5,000件かを確認する。
3. 各投稿について必須キー、文字列型、空白でない本文を検証する。
4. `url`は`https:`プロトコルだけを許容する。
5. `postedAt`は`Date.parse`可能で、ISO 8601のタイムゾーン指定を含むことを確認する。
6. `id`の重複を検出する。問題があれば`入力行 N: 理由`の形式でまとめて返す。

## 4. 正規化の詳細

```text
1. text.normalize('NFKC')
2. 小文字化
3. ignoreUrls=trueなら https:// または http:// から始まる連続文字列を空文字列へ置換
4. ignoreMentions=trueなら @英数字_ の文字列を空文字列へ置換
5. 改行を空白へ置換し、連続空白を1個へ畳み込み、前後をtrim
```

URL・メンション除去後に空文字列となった投稿は、近似一致の候補にしない。完全一致でも空文字列だけの一致はクラスタ化しない。

## 5. クラスタ生成の手順

1. 全投稿を正規化して`normalizedText`を付与する。
2. 空でない同じ正規化文字列をMapに入れ、異なるアカウントを2つ以上含むグループを完全一致クラスタにする。
3. 完全一致クラスタに属する投稿を近似判定の対象から除く。
4. 近似一致が有効なら、残りの異なるアカウント間の投稿ペアについてJaccard類似度を算出する。
5. 閾値以上のペアをUnion-Findで結合する。自己ペアと同一アカウントのペアは比較しない。
6. 連結成分ごとに異なるアカウントが2つ以上あるものを近似一致クラスタにする。
7. 完全一致を先、次に類似度・アカウント数・先頭投稿日時の降順で並べ、クラスタIDを採番する。

## 6. CSVのエスケープ

セル内の二重引用符は`""`へ置換し、すべてのセルを二重引用符で囲む。改行とカンマを含む投稿本文もこの方式で安全に出力する。値の先頭が`=`, `+`, `-`, `@`のときはCSVインジェクションを防ぐため先頭にアポストロフィを付ける。ただしアカウント表示用の`@`は、CSVではアポストロフィ付きの値になることを仕様とする。

## 7. テスト観点

| 観点 | 例 |
| --- | --- |
| 完全一致 | 大文字・全半角・空白・URL/メンションの差だけの投稿が同一クラスタになる。 |
| アカウント条件 | 同一アカウントだけの重複は結果に含まれない。 |
| 近似一致 | トークンが十分に重複する異アカウント投稿が閾値で検出される。 |
| 非検出 | 閾値未満、空テキスト、別内容はクラスタにならない。 |
| 入力保護 | 不正URL、不正日時、重複ID、上限超過、CSV列不足を拒否する。 |
| 出力保護 | カンマ・改行・数式を含む値を安全なCSVとして出力する。 |
