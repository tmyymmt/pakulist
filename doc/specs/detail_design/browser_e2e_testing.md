# ブラウザE2Eテスト詳細設計

## 1. 目的

本書は、pakulistのローカルWebアプリについて、単体テストでは検証できない画面上のファイル入力、状態遷移、設定、結果表示、CSV出力、外部リンクの安全性をPlaywright Chromiumで回帰検証する仕様を定義する。

## 2. 実行環境

| 項目 | 方針 |
| --- | --- |
| テストランナー | Playwright Test |
| ブラウザ | Playwright Chromium |
| サーバー | `node server.js`をテスト中にポート4173で起動する |
| テストデータ | リポジトリ内の架空フィクスチャ、またはテスト内のメモリ上ファイルのみを利用する |
| 外部通信 | X API、認証、実X投稿の取得は行わない。外部リンクは属性を検証し、実クリックしない。 |

## 3. テストシナリオ

| ID | シナリオ | 主な検証 |
| --- | --- | --- |
| E2E-01 | 正常JSON | 投稿ファイル読込、検出クラスタ、証拠表示、CSVダウンロード。 |
| E2E-02 | 投稿本文の安全表示 | HTMLに見える本文がテキストとして表示され、子要素として実行・挿入されない。 |
| E2E-03 | 外部リンク | `target=_blank`、`noopener`、正しい投稿URLを持ち、利用者クリック前に別タブを開かない。 |
| E2E-04 | 正常CSVと設定 | CSV読込、URL・メンション無視の切替、設定変更後の検出結果。 |
| E2E-05 | 同一アカウント除外 | 同一アカウント内だけの重複を結果に出さない。 |
| E2E-06 | 入力エラー | 不正拡張子、壊れたJSON、CSVヘッダ不足、URL・日時不正、重複ID、5,000件超過の理由付きエラー。 |
| E2E-07 | 意味的APIの状態確認 | ローカル意味的APIのヘルス応答をモックし、有効化時だけ意味的設定を利用可能にする。 |
| E2E-08 | LLMによる候補再構成 | 文字列近似の`non_match`を最終結果から除外し、発見候補の`match`を追加し、集計にLLM追加・除外件数を表示する。 |

## 4. 実行コマンド

```bash
cd app
npm run test:e2e
npm run test:all
```

`test:all`は構文検査、単体テスト、性能回帰チェック、E2Eテストを順に実行する。E2Eの意味的APIはPlaywrightのルートモックを使い、実OrcaRouter、APIキー、実投稿データへ通信しない。GitHub Actionsは同じコマンドをNode.js 22とPlaywright Chromium上で実行する。

## 5. CI失敗時の扱い

E2E失敗時は、Playwrightが失敗時のトレースとスクリーンショットを出力する。機能変更に伴って期待値を変える場合は、システム仕様、単体テスト、E2Eテスト、性能基準への影響を同じPRで確認する。実OrcaRouterはE2Eで利用せず、実API確認は利用者提供キーを使うローカル手動検証に限定する。実X API、保存、認証、外部リンクのクリックなど後続フェーズの機能は、別の明示的なE2Eシナリオを追加するまで本テストの対象に含めない。
