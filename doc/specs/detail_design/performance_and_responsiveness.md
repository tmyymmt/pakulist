# 検出性能・応答性の詳細設計

## 1. 目的

pakulistは最大5,000件の投稿を受け入れる。近似一致は比較対象の投稿ペアが増えるため、処理時間とメモリの上限を定義し、再現可能なベンチマークで回帰を検知する。本書は現行ローカルWeb MVPの性能要件を定義する。

## 2. 測定条件

ベンチマークはNode.js 22上で、`app/benchmarks/detection-performance.mjs`を実行する。外部API・ネットワーク・ディスクI/Oを含めず、入力検証後の`findDuplicateClusters`の処理時間を`performance.now()`で測定する。

| シナリオ | データ特性 | 件数 | 期待するクラスタ |
| --- | --- | ---: | ---: |
| 完全一致 | 10投稿ごとに同一本文、200アカウントへ分散 | 1,000 / 5,000 | 100 / 500 |
| 近似一致 | 50投稿ごとに共通10トークンと個別1トークンを持つ本文、200アカウントへ分散、閾値0.80 | 1,000 / 5,000 | 20 / 100 |

ベンチマークは開発機・CIの相対的な回帰検知に使う。実際のブラウザ性能は端末、拡張機能、投稿本文のトークン分布に依存するため、サービス水準の保証値とは扱わない。

## 3. 性能基準

`npm run bench:check`は次の時間を超えると失敗する。上限は、一般的な開発・CI環境で変動を許容しつつ、近似比較が利用者操作を大きく妨げないことを確認するための回帰ガードである。

| シナリオ | 1,000件 | 5,000件 |
| --- | ---: | ---: |
| 完全一致 | 1,000ms以下 | 2,500ms以下 |
| 近似一致 | 1,500ms以下 | 5,000ms以下 |

## 4. 実測結果

2026-08-12にUbuntu sandbox・Node.js 22で同一ベンチマークを測定した。

| 実装段階 | 完全一致 1,000件 | 近似一致 1,000件 | 完全一致 5,000件 | 近似一致 5,000件 |
| --- | ---: | ---: | ---: | ---: |
| 総当たり・比較ごとのトークン化 | 15.5ms | 3,573.1ms | 52.7ms | 85,519.6ms |
| トークン事前計算と集合サイズ上界 | 16.2ms | 155.3ms | 55.6ms | 3,802.7ms |
| 接頭辞フィルタによる候補索引 | 29.4ms | 99.4ms | 62.8ms | 312.0ms |

最終段階では、近似一致5,000件の同一条件ベンチマークが5秒の回帰ガードを下回った。最適化前と最終段階を比較すると、近似一致5,000件は約274倍高速化した。ただし、ベンチマークのトークン分布に依存するため、異なる入力で同じ倍率を保証するものではない。

## 5. 近似一致の候補絞り込み

近似一致の計算は、すべての投稿ペアについてトークン化・Jaccard計算を繰り返さない。次の順で処理する。

1. 各投稿の正規化済み本文を一度だけトークン集合へ変換する。
2. 全投稿におけるトークン頻度と文字列順からグローバルなトークン順序を作る。
3. Jaccard閾値`τ`に対して、各トークン集合の接頭辞長を`|S| - ceil(τ × |S|) + 1`として求める。
4. 接頭辞トークンを索引化し、共通接頭辞を持つ投稿ペアだけを候補にする。
5. 同一アカウント、空集合、トークン数比が閾値未満の候補を除外する。
6. 残った候補だけへJaccard類似度を計算し、閾値以上をUnion-Findでクラスタ化する。

共通接頭辞を持たない集合は、指定閾値以上のJaccard類似度にならないため、候補から除外しても検出結果を失わない。標準JSON/CSV、X API Search JSON、完全一致判定、同一アカウントの除外、既存の閾値範囲は変えない。

## 6. 利用者向けの応答性

解析開始時は、結果領域へ「ブラウザ内で検出処理を実行しています」と表示し、次の描画フレームを待ってから同期解析を開始する。解析中はファイル選択、判定設定、実行ボタンを無効化し、同じ入力に対する並行実行や設定変更を防ぐ。解析終了後は必ず操作を復帰する。

現行の性能基準を満たす間は、Web Workerや中断ボタンを導入しない。実測または利用者検証で5,000件の近似一致が5秒を継続的に超える、またはUI応答性の問題が再現した場合は、Workerへの分離、進捗通知、キャンセル用の新規Issueを作成する。

## 7. 実行方法

```bash
cd app
npm run bench
npm run bench:check
```

`bench:check`は基準超過時に非ゼロで終了する。性能上限を変更する場合は、測定環境、入力特性、変更前後の実測値、利用者への影響を同じPRへ記録する。
