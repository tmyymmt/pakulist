# UC-03 時系列コピー候補検知の詳細設計

## 1. 目的と境界

UC-03は、指定した起点アカウントの投稿より**後に**出た類似投稿を、手動確認のためのコピー候補として抽出する。これは投稿時刻と決定的な文字列類似度に基づく候補抽出であり、著作権侵害、不正利用、利用規約違反その他の法的結論を示すものではない。

現行のローカルWebアプリは、利用者が正規に取得してローカルに保存した投稿データだけを処理する。X API接続、認証、トークン、データ保存、AI意味類似、スクリーンショット取得、自動通報は本機能の対象外である。

## 2. 入力モデル

既存の投稿入力形式に加え、任意の設定`originAccount`を受け取る。

| 設定 | 型 | 正規化 | 意味 |
| --- | --- | --- | --- |
| `originAccount` | 文字列 | 前後空白と先頭の`@`を除去。30文字以内。 | UC-03の起点アカウント。空文字列なら従来の対称的な重複検出を行う。 |
| `threshold` | 数値 | 0.50〜1.00 | 近似一致時に起点投稿と候補投稿の直接比較へ使う閾値。 |

起点アカウントは大文字・小文字を区別せず照合する。指定アカウントの投稿がクラスタにない場合、そのクラスタはコピー候補として出力しない。

## 3. 判定手順

1. 既存の完全一致・近似一致クラスタを生成する。
2. 起点アカウントが未指定なら、既存のクラスタをそのまま返す。
3. 指定されていれば、クラスタ内にある起点アカウントの投稿を投稿時刻順に並べ、最も早い投稿を`originPost`にする。
4. 起点アカウント以外の投稿のうち、`postedAt`が`originPost`より厳密に後の投稿だけを候補にする。
5. 完全一致では類似度を1.00とする。近似一致では、候補投稿と`originPost`を直接Jaccard比較し、閾値以上のものだけを残す。
6. 候補が1件以上ある場合だけ、起点投稿と候補投稿を同じクラスタとして返す。

| 時刻関係 | 取り扱い | 理由 |
| --- | --- | --- |
| 候補が起点より後 | 候補に含める | UC-03の「後から類似投稿」の条件を満たす。 |
| 候補が起点と同時刻 | 含めない | 時刻だけでは前後関係を確定できない。 |
| 候補が起点より前 | 含めない | 起点投稿をオリジナルとみなす条件に反する。 |
| 起点アカウントの複数投稿 | 最も早い一致投稿を起点にする | 再現可能で保守的な基準にする。 |

日時欠損・不正日時は既存の入力検証で拒否するため、時系列判定に入らない。

## 4. 出力モデル

コピー候補モードのクラスタは、通常の`clusterId`、`matchType`、`similarity`、投稿証拠に加え、次のフィールドを持つ。

| フィールド | 内容 |
| --- | --- |
| `originAccount` | 起点投稿のアカウント。 |
| `originPostId` | 起点投稿ID。 |
| `copyCandidateCount` | 後発候補の件数。 |
| `posts[].copyRole` | `origin`または`candidate`。 |
| `posts[].delaySeconds` | 起点投稿からの秒差。起点は0。 |

CSVには`originAccount`、`originPostId`、`copyRole`、`delaySeconds`を追加する。通常の重複検出ではこれらの列を空欄とし、既存の全行出力を維持する。

## 5. 画面仕様

判定設定に「起点アカウント（UC-03）」を置く。利用者が起点アカウントを入力して解析すると、結果概要にコピー候補クラスタ数・後発候補数を表示する。各証拠投稿には「起点投稿」または「後発コピー候補（n時間後）」を表示する。画面は候補判定が法的結論でないことを明示する。

## 6. テスト

単体テストでは、完全一致・近似一致における後発候補、先行・同時刻投稿の除外、起点アカウント不在、不正設定、CSVの時刻差列を検証する。E2Eでは、起点アカウント入力、起点・候補の画面表示、先行・同時刻投稿の非表示、CSV出力を検証する。
