# X API取得の利用枠・従量課金 詳細設計

## 1. 目的と適用範囲

本書は、有償版がX APIを利用して投稿を取得する場合の、販売方式、利用枠、費用見積り、実行前予約、消費計上、停止、精算、監査の要件を定義する。X APIは高コスト又は契約条件の変更を伴い得るため、**無制限の取得は提供しない**。提供方式は、利用者又は契約ごとに選択する**従量課金**又は**定額利用枠**だけとする。

現行OSS MVPは、本書の対象外である。現行MVPは外部API、利用者認証、決済、使用量保存、サーバー側データ保存を実装せず、利用者が選択したローカルファイルだけをブラウザ内で処理する。

> X API取得を有効にできるのは、`x_data_acquisition_policy.md`のDAR-01〜DAR-10、`external_data_governance.md`のGOV-01〜GOV-18、Issue #32の承認・運用開始ゲートを満たした後だけである。料金方式又は利用枠の存在は、取得・保存・表示の許可を意味しない。

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| 提供者原価 | Xとの契約、課金プラン、エンドポイント、実消費量から算出するサービス運営者側の原価。 |
| 販売単位 | 有償版が利用者に販売・表示する、設定可能な取得利用単位。X側の請求単位と同一であることを前提としない。 |
| 利用枠 | 契約期間内に利用できる販売単位の上限。定額契約であらかじめ付与する。 |
| 従量課金 | 事案又は取得実行ごとに、利用者が提示された上限額の範囲で販売単位を購入する方式。 |
| 予約 | 実行前に、利用枠又は従量課金の上限額を確保し、同じ取得が二重に実行・請求されないようにする処理。 |
| 精算 | 実消費量と実行結果に基づき、予約を確定、余剰解放、又は停止として記録する処理。 |
| 料金カタログ | X側の契約条件・単価、販売単位、販売価格、警告閾値、停止閾値、有効期間を版管理するサーバー側設定。 |

## 3. 提供方式と料金プラン

### 3.1 共通原則

各料金プランは、ひとつの有効な料金カタログ版に紐づく。料金カタログには、対象エンドポイント、X側の請求・レート条件、原価推定規則、販売単位、販売価格、通貨、税の扱い、警告・停止閾値、適用開始・終了時刻を含める。価格・枠・原価の値をブラウザ、公開リポジトリ、アプリ定数へ固定してはならない。

販売単位は、Xとの契約で認められた計測軸から選択する。たとえばリクエスト数、取得件数、又は契約固有の消費量である。ひとつの料金カタログ版は販売単位をひとつだけ選び、利用者へその名称、換算規則、上限を明示する。X側の単価又は請求単位が不明、期限切れ、又は契約と不整合な場合は、見積りも取得も開始してはならない。

| 方式 | 利用者への提供 | 実行前条件 | 超過時の既定動作 |
| --- | --- | --- | --- |
| 従量課金 | 事案又は取得実行ごとに、最大販売単位と最大請求額を提示し、利用者が明示承認する。 | 有効な料金カタログ、見積り、支払手段又は与信、上限額の承認、予約。 | 実行を停止し、追加購入・縮小した検索条件・管理者審査・翌期までの保留を提示する。承認なしの自動超過課金は行わない。 |
| 定額利用枠 | 契約期間ごとに、含まれる販売単位、期限、繰越・失効、超過可否を明示する。 | 残利用枠、対象期間、有効な料金カタログ、予約。 | 実行を停止する。超過従量を別途明示承認している場合だけ、従量課金として新たに予約する。 |

無料枠、無制限枠、又は「X APIの実費を問わず取得を継続する」プランは作らない。販促・試用を行う場合も、費用上限を持つ管理者承認済みの利用枠として扱い、本書の予約・停止・監査を適用する。

### 3.2 プランの最低スキーマ

```json
{
  "planId": "paid-x-search-standard",
  "planVersion": "2026-08-01",
  "billingMode": "metered",
  "billingUnit": "configured-provider-usage-unit",
  "currency": "JPY",
  "includedUnits": 0,
  "overageAllowed": false,
  "maximumCharge": 0,
  "warningThresholdPercent": 80,
  "hardStopThresholdPercent": 100,
  "catalogVersion": "x-contract-config-version",
  "effectiveFrom": "2026-08-01T00:00:00Z",
  "effectiveTo": "2026-08-31T23:59:59Z"
}
```

`billingMode`は`metered`又は`included_quota`だけを許容する。`includedUnits`は従量課金では0、定額利用枠では0以上とする。`maximumCharge`は、従量課金の利用者承認上限、又は定額利用枠の超過従量を利用者が承認した場合の上限を表す。数値の0は無料ではなく、当該プラン又は超過課金で利用できる追加金額がないことを表す。

## 4. 取得前の見積りと予約

取得要求は、認証済み利用者、事案ID、目的コード、対象アカウント、検索条件、期間、選択プラン、利用者の明示承認を必須とする。検索条件はDAR-04、DAR-05、GOV-01に従い、オンデマンドかつ最小化したものだけを受け付ける。

実行前にサービスは、Xの契約上許容される範囲での最大取得件数又は最大消費量を見積もる。見積りは、料金カタログ版、プラン版、販売単位、残利用枠、最大請求額、対象エンドポイント、見積りの有効期限を利用者へ表示する。見積りに必要な単価・換算規則が欠ける場合、又は見積りが利用枠・上限額を超える場合、取得を開始しない。

```text
予約販売単位 = min(見積り上限販売単位, プランで許容される残利用枠又は承認済み購入上限)
予約原価上限 = 料金カタログ(提供者原価換算規則, 予約販売単位)
予約販売上限 = 料金プラン(販売価格規則, 予約販売単位, 税規則)
```

予約は、利用者ID、事案ID、プラン版、料金カタログ版、見積り、予約日時、有効期限、状態、冪等キーを持つ。冪等キーは同じ利用者・事案・正規化検索条件・カタログ版・承認内容からサーバー側で生成し、未精算の同一予約が存在する場合は再利用する。クライアントが送る価格、残利用枠、消費量、状態を信頼してはならない。

| 予約状態 | 遷移条件 | 取得実行 |
| --- | --- | --- |
| `quoted` | 見積りを作成したが、利用者承認又は予約が未完了。 | 不可 |
| `reserved` | 残利用枠又は承認済み従量枠を確保した。 | 可 |
| `running` | サーバー側でX API呼び出しを開始した。 | 実行中 |
| `settled` | 実消費量・結果・請求又は利用枠消費を確定した。 | 完了 |
| `released` | 未開始、期限切れ、又は消費なしで予約を解放した。 | 不可 |
| `blocked` | 枠不足、上限超過、価格不明、承認不備、規約不整合、レート制限又は運用停止で拒否した。 | 不可 |

## 5. 実行中の消費計上と停止

サーバー側のX APIアダプターは、呼び出しごとに料金カタログの計測規則に従って実消費量を更新する。実消費量、残利用枠、予約販売上限、提供者原価上限、レート制限残量を原子的に判定し、いずれかの停止条件に達した場合は、次のX API呼び出しを開始しない。

| 事象 | 必須動作 | 利用者への表示 |
| --- | --- | --- |
| 利用枠の80%到達 | 警告を記録・表示する。残量と縮小可能な検索条件を示す。 | 残利用枠、警告理由、超過時の選択肢。 |
| 利用枠又は最大請求額の100%到達 | 取得キューを停止し、未開始の呼び出しを実行しない。 | 枠不足又は請求上限到達、追加承認・次期更新・検索縮小の選択肢。 |
| 提供者原価の見積りを超過しそう | 取得を停止し、料金カタログ・契約・検索範囲を管理者が再確認するまで保留する。 | 原価・契約条件の再確認が必要である旨。 |
| 429又はレート制限残量不足 | `Retry-After`又はXのリセット時刻に従い、予約を保持して保留する。予約期限内に再開できなければ未消費分を解放する。 | 再試行予定又は保留・解放の状態。 |
| 料金カタログ期限切れ、単価不明、契約不整合 | 取得を開始・再開しない。 | 管理者による料金・契約確認が必要である旨。 |
| GOV-04の削除・利用不能化又は規約逸脱 | 取得・表示・出力を停止し、データ削除又は非表示処理を優先する。 | 対象データが利用不能である旨。 |

取得中に利用者が検索条件を広げる場合、既存予約を変更してはならない。新しい見積り、明示承認、予約を作成してから別実行として扱う。これにより、利用者承認なしの上限超過と二重請求を防ぐ。

## 6. 精算、調整、返金の責任分界

精算は、X API呼び出しの実消費量と、取得結果の状態に基づいて行う。取得した投稿の本文、URL、アカウント、検索語そのものを課金台帳へ保存してはならない。課金台帳は、予約ID、利用者ID、事案ID、プラン・カタログ版、販売単位、予約・確定・解放数量、金額、通貨、税、状態、時刻、決済参照IDだけを保持する。

| 結果 | 定額利用枠 | 従量課金 | 調整責任 |
| --- | --- | --- | --- |
| 実行前に拒否・取消・期限切れ | 予約枠を全量解放する。 | 与信・予約を取消し、請求しない。 | サービス運営者。 |
| 429等で消費なし | 未消費分を全量解放する。 | 与信・予約を取消し、請求しない。 | サービス運営者。 |
| 一部取得後に停止 | Xの契約上の実消費量だけを確定し、未消費予約を解放する。 | 明示承認済み上限を超えない実消費分だけを確定する。 | サービス運営者は利用明細と停止理由を提示する。 |
| 提供者側の計測・請求訂正 | 利用枠調整は承認済みの調整手順でのみ行う。 | 返金・追徴の可否は決済規約と法令に従い、利用者へ明細を通知する。 | 決済事業者・会計・法務を含む運用責任者。 |

本書は支払処理、消費税、返金可否、会計仕訳、法的請求書の実装を確定するものではない。これらは販売国、決済事業者、契約、法令に応じて有資格の会計・法務・決済担当者が別途承認する。X Contentの削除と課金記録の保持は別目的であり、GOV-04〜GOV-06に従うデータ削除が、法令・会計上必要な最小限の非内容型取引記録まで自動削除することを意味しない。

## 7. アクセス制御・監査・表示

料金カタログの作成・有効化・停止、利用枠の付与・調整、超過例外の承認、返金・調整は、利用者の取得操作から分離した管理権限でだけ実行する。料金カタログを変更した場合、実行中・予約済みの取得へ遡及適用してはならない。予約時点のカタログ版とプラン版を精算まで保持する。

GOV-15の監査記録に加え、課金・利用枠の監査記録は、予約ID、状態遷移、プラン版、カタログ版、見積りと確定した販売単位、原価区分、警告・停止理由、管理者承認IDを記録する。本文、URL、アカウント、検索語の原文、トークン、決済手段の完全な情報、認証ヘッダーは記録しない。

利用者には、取得前にプラン名、販売単位、残利用枠又は最大請求額、見積り、上限、料金カタログの有効期限、超過時の選択肢を表示する。取得後には、実行状態、確定又は解放された販売単位、請求額又は残利用枠、停止理由、データの保持・削除に関する注意を表示する。利用者は、料金カタログ・契約の不明又は失効を回避する目的で取得を強行できない。

## 8. テストと導入ゲート

| 検証領域 | 最低限の確認 |
| --- | --- |
| 見積り | 単価・換算規則・カタログ有効期限が不足する場合に取得を拒否する。 |
| 予約 | 同一冪等キーで二重に利用枠又は従量与信を確保しない。 |
| 停止 | 80%警告、100%停止、原価上限、429、料金期限切れ、契約不整合をテストする。 |
| 精算 | 未実行・消費なし・一部実行で、確定・解放・明細が整合することをテストする。 |
| 権限 | 利用者が価格、残利用枠、カタログ、精算状態を改ざんできず、秘密情報を返さないことをテストする。 |
| データ保護 | 課金・監査ログへX Content、検索語原文、トークン、決済情報を残さないことをテストする。 |

実装を開始する前に、Xとの書面許可・課金契約・エンドポイント条件、料金カタログの実値、販売価格、決済・税・返金の運用責任、サーバー側シークレット、認証・事案別権限、削除・監査・障害対応を承認する。これらが未確定の場合は、仕様を維持しても有償版のX API取得を有効化しない。
