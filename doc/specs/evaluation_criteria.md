# 評価基準と実装状況

本書は、pakulistの事業性、完成度、技術性、セキュリティを横断して確認するための評価基準である。ここでいう「現行MVP」は、正規に取得済みの投稿データを利用者がローカルで選択し、ブラウザ内で決定的な重複検出とCSV出力を行うOSS版を指す。外部データ取得、AI、永続化、認証を伴う機能は後続フェーズとして扱う。

## 1. ステータスの定義

| 表記 | 意味 |
| --- | --- |
| 実装済み | 要件に対応する実装と、少なくとも自動テストまたは手動確認の証跡がある。 |
| 一部確定 | 方向性または一部の実装は存在するが、成立を示す数値、利用者検証、全要件への対応、または後続設計が未完了である。 |
| 未着手 | 方針・実装・検証のいずれも、これから着手する。 |

> **注意**: 現行MVPの実装済みは、製品全体としての完成を意味しない。特に、複数アカウントの比較データをどの正規経路で取得・利用するかは未決定であり、自分自身のXアーカイブだけでは主ユースケースを満たさない。

## 2. 現行MVPで実装・検証済みの範囲

現行MVPには、ローカル静的Webアプリ、UTF-8のCSV/JSON入力、入力検証、完全一致・決定的な近似一致、異なるアカウントだけを対象にしたクラスタリング、証拠表示、CSV出力、および手動通報のための外部リンクが実装されている。入力データと結果はサーバーへ保存・送信せず、外部API呼び出しと自動通報は行わない。

| 領域 | 実装・検証済みの内容 | 証跡 |
| --- | --- | --- |
| 入力・検出 | CSV/JSONの検証、正規化、完全一致、Jaccard類似度による近似一致、異なるアカウントだけを含むクラスタの抽出 | `app/src/detection.js`、`app/test/detection.test.js` |
| 証拠・出力 | アカウント、投稿URL、投稿日時、本文、判定種別、類似度の表示とCSV出力 | `doc/specs/system_spec/spec.md` §4〜§6、`20260812_browser_check.md` |
| 安全性 | ブラウザ内処理、静的配信、POST拒否、入力のテキスト表示、外部リンクの利用者操作 | `app/server.js`、`doc/specs/architecture_design/local_web_mvp.md` §5、`20260812_0000-handover.md` |
| 品質確認 | 構文検査と10件の単体テスト、サンプルデータ7件による完全一致・近似一致・CSV保存のブラウザ確認 | `app/package.json`、`app/test/detection.test.js`、`20260812_browser_check.md` |

## 5. 次に進める順序

現行MVPの品質を高める作業と、後続フェーズへ進むための方針決定を混同しない。まず、現在の実装・検証の実態を本書で可視化したうえで、次の順に進める。

| 優先度 | 課題 | 理由 |
| --- | --- | --- |
| P0 | #11 評価基準の更新 | 実装済みMVPと未達事項の境界を正しく共有する。 |
| P0 | #2 他アカウント投稿を正規に取得・利用する経路の決定 | 自分のXアーカイブだけでは主ユースケースを満たせないため、後続実装の前提を決める。現行MVPへのX API・自動収集の実装は含まない。 |
| P1 | #6 性能基準・計測、#10 ブラウザE2E | 現行MVPの信頼性と再現性を高める。 |
| P1 | #3 入力アダプター、#9 データ管理方針 | #2で採用した正規データ経路を、安全にMVPの入力形式へ接続する。 |
| P2 | #4、#5、#7、#8、#12 | コピー候補検知、証拠拡張、関係性グラフ、AI、事業検証を後続フェーズで進める。 |
