# 評価基準と実装状況

本書は、pakulistの事業性、完成度、技術性、セキュリティを横断して確認するための評価基準である。ここでいう「現行MVP」は、正規に取得済みの投稿データを利用者がローカルで選択し、ブラウザ内で決定的な重複検出とCSV・HTML証拠パッケージ出力を行うOSS版を指す。外部データ取得、AI、永続化、認証を伴う機能は後続フェーズとして扱う。

## 1. ステータスの定義

| 表記 | 意味 |
| --- | --- |
| 実装済み | 要件に対応する実装と、少なくとも自動テストまたは手動確認の証跡がある。 |
| 設計済み | 実装前提、データ境界、契約又は評価方法を定義したが、外部接続・実データ・運用検証は未実施である。 |
| 一部確定 | 方向性又は一部の実装は存在するが、成立を示す数値、利用者検証、全要件への対応が未完了である。 |
| 未着手 | 方針・実装・検証のいずれも、これから着手する。 |

> **注意**: 現行MVPの実装済みは、製品全体としての完成を意味しない。複数アカウントの比較データを本番サービスで取得・利用するには、公式APIの利用目的承認、資格情報、保持・削除・権限制御、運用体制を別途満たす必要がある。利用者自身の単一アカウントアーカイブだけでは主ユースケースを満たさない場合がある。

## 2. 現行MVPで実装・検証済みの範囲

現行MVPには、ローカル静的Webアプリ、UTF-8のCSV/JSON入力、保存済みX API Search JSONのローカル変換、入力検証、完全一致・決定的な近似一致、異なるアカウントだけを対象にしたクラスタリング、UC-03の時系列コピー候補、証拠表示、CSV・HTML証拠パッケージ出力、手動通報のための外部リンクが実装されている。入力データと結果はサーバーへ保存・送信せず、外部API呼び出しと自動通報は行わない。

| 領域 | 実装・検証済みの内容 | 証跡 |
| --- | --- | --- |
| 入力・検出 | CSV/JSONの検証、保存済みX API Search JSONのローカル変換、正規化、完全一致、Jaccard類似度による近似一致、異なるアカウントだけを含むクラスタ、UC-03の後発候補抽出 | `app/src/detection.js`、`app/test/detection.test.js` |
| 証拠・出力 | アカウント、投稿URL、投稿日時、本文、判定種別、類似度、時刻差の表示、CSV、HTML証拠パッケージ | `doc/specs/system_spec/spec.md` §4〜§6、`doc/specs/detail_design/evidence_package.md`、`app/src/evidence.js` |
| 安全性 | ブラウザ内処理、静的配信、POST拒否、入力のテキスト表示、CSVインジェクション対策、HTMLエスケープとCSP、利用者操作による外部リンク | `app/server.js`、`app/src/detection.js`、`app/src/evidence.js` |
| 品質確認 | 構文検査、単体テスト30件、性能回帰4シナリオ、Playwright E2E 6シナリオ、CI | `app/package.json`、`app/test/`、`app/benchmarks/`、`app/e2e/`、`.github/workflows/test.yml` |

## 3. ユースケースのカバー状況

| ユースケース | 現行MVPでカバーする範囲 | 未カバーの範囲 | 後続の関連課題 |
| --- | --- | --- | --- |
| UC-01: 競合他社の過剰なボット投稿を通報する | 正規に用意された複数アカウントの投稿データから、同一・近似文面の候補、CSV、HTML証拠パッケージを作る。 | 本番サービスにおける他アカウント投稿の公式取得・利用承認、実データでの運用検証。 | 外部データ連携の承認・運用 |
| UC-02: 同じ投稿をしている複数アカウントを通報する | 同一文面又はトークン類似度が閾値以上の異アカウント投稿をクラスタ化し、手動確認向けに出力する。スクリーンショットは自動取得せず、利用者の最小限の手動対応に限定する。 | 本番データ経路、通報後の効果測定、利用者価値の検証。 | 外部データ連携の承認・運用、利用者検証 |
| UC-03: パクツイを検知して通報する | 起点投稿又は起点アカウントを指定し、時刻順に後発の完全一致・近似一致候補と時刻差を出力する。 | 意味的な言い換えの実測評価、AI連携、原価検証、本番データ経路。 | #8、外部データ連携の承認・運用 |

## 5. 次に進める順序

初期のP0・P1・P2の仕様・実装課題は完了済みである。現在は、#32の外部データ連携の承認・運用、#33の利用者検証、#35のX API利用枠・従量課金設計、#8の実AI評価がオープンである。実AI連携又は有償X API取得は、資格情報、データ権限、実モデル・X契約の単価、料金カタログ、認証、統合テストが揃うまで有効化しない。

| 優先度 | 課題 | 理由 |
| --- | --- | --- |
| P0 | #32 正規な外部データ連携の承認・運用開始判断 | 比較対象の実データを扱えなければ、主ユースケースを本番サービスで成立させられないため。 |
| P1 | #33 利用者検証、#35 X API利用枠・従量課金の設計 | 価格、利用枠、AI、グラフ、保存サービスを実装で先取りせず、原価上限と利用者価値を確認するため。 |
| P2 | #8の実AI精度・原価・障害時統合検証 | APIキー、データ権限、モデル・単価の確定後に、限定条件で検証するため。 |
