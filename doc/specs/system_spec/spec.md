# システム仕様: ローカルWebアプリMVP

## 1. 目的と適用範囲

本仕様は、正規な手段で利用者自身が取得したX投稿データを入力として、異なる複数アカウント間の重複投稿を検出し、手動通報のために確認できる証拠リストを生成するローカルWebアプリの振る舞いを定義する。アプリは完全一致と決定的な近似一致をブラウザ内で検出する。さらに、利用者が明示的に有効化し、ローカルのOrcaRouter意味的類似APIを起動した場合だけ、候補を意味的に再評価する。

> 本アプリは重複投稿を**検出・整理**する補助ツールであり、違反の最終判断または通報操作を自動化しない。

認証、投稿データの保存、課金、利用枠、X APIによる取得は本MVPの対象外である。意味的類似APIは利用者提供のキーを一時的なローカルプロセス環境変数に設定する試作であり、管理型サービスではない。

## 2. 初期状態

アプリ起動時はサンプルデータを読み込まず、ファイル未選択・結果0件の状態で表示する。近似一致判定は有効、類似度閾値は **0.80**、URL・メンションの無視は有効、意味的類似判定は無効とする。入力済みデータや結果はブラウザを閉じると失われる。

意味的類似判定を無効のまま実行する場合、投稿本文・アカウント情報・投稿URLを外部サービスへ送信しない。意味的類似判定を有効にした場合だけ、§4.5の候補ペア本文がローカルWebサーバーを経由してローカル意味的APIへ送られ、同APIがOrcaRouterへ最小化済みの要求を送信する。

## 3. 入力仕様

### 3.1 受入形式

ファイル選択でUTF-8の`.csv`または`.json`を1ファイル読み込む。ファイル内容はブラウザ内で解析する。CSVの区切り文字はカンマ、引用符はRFC 4180相当の二重引用符とする。

| 項目 | JSONキー / CSV列名 | 必須 | 型・形式 | 説明 |
| --- | --- | --- | --- | --- |
| 投稿ID | `id` | 必須 | 1文字以上の文字列 | 投稿を一意に識別するID。 |
| アカウント識別子 | `account` | 必須 | 1〜30文字の文字列 | `@`は任意。画面では先頭に`@`を補う。 |
| 投稿URL | `url` | 必須 | `https://`で始まるURL | 証拠として利用者が開く投稿リンク。 |
| 投稿日時 | `postedAt` | 必須 | ISO 8601形式 | タイムゾーンを含む日時。 |
| 投稿本文 | `text` | 必須 | 空白以外を1文字以上含む文字列 | 判定対象となる投稿本文。 |

JSONは上記オブジェクトの配列、または`posts`キーに同配列を持つオブジェクトを受け入れる。投稿IDはファイル内で重複してはならない。入力件数の上限は5,000件とする。

許可済みのX API v2 Searchレスポンスを保存したJSONも受け入れる。この形式では、`data[].id`、`data[].author_id`、`data[].created_at`、`data[].text`と、`includes.users[]`の`id`・`username`を結合し、標準形式へローカル変換する。`author_id`に対応する`username`がない場合は、誤った投稿URLを生成せず入力エラーとする。変換の詳細は`doc/specs/detail_design/x_api_input_adapter.md`を参照する。

### 3.2 入力エラー

拡張子、文字コード、必須項目、URL、日時、投稿ID重複、上限件数のいずれかに不備がある場合、解析・検出を中止する。画面は利用者が修正できるよう、原因と該当行番号または配列番号を表示する。

## 4. 検出仕様

### 4.1 テキスト正規化

比較前に投稿本文をUnicode NFKCへ正規化する。小文字化、改行と連続空白の単一空白化、前後空白の除去を行う。設定が有効な場合、URLと`@`から始まるメンションは除去する。ハッシュタグ、絵文字、句読点は保持する。

### 4.2 完全一致

正規化後の文字列が完全に一致する投稿を候補とする。候補に異なるアカウントが2つ以上含まれる場合、判定種別`完全一致`、類似度`1.00`として検出する。同一アカウント内だけで重複する投稿は結果に表示しない。完全一致クラスタの投稿は意味的類似APIの候補から除外し、外部送信しない。

### 4.3 決定的な近似一致

近似一致が有効な場合、完全一致にならなかった投稿ペアを、正規化済み文字列から作成した単語トークンのJaccard類似度で比較する。類似度が指定閾値以上のペアを同一クラスタに連結する。初期閾値は0.80で、利用者は0.50から1.00まで0.05刻みで変更できる。空トークン同士は一致とみなさず、同一アカウントだけのクラスタは除外する。

この手法は決定的であるが、語順の変更、同義語、意味的な言い換えを正確に検出するものではない。意味的類似判定を無効にした場合、決定的な近似一致が最終結果となる。

### 4.4 意味的候補の選定

意味的類似判定は通常の重複クラスタモードでのみ利用できる。UC-03の起点指定モードでは利用しない。アプリは次の順序で、異なるアカウント間の候補を作る。

| 候補種別 | 対象 | 優先順位 | 送信条件 |
| --- | --- | --- | --- |
| 文字列近似候補 | 決定的な近似一致クラスタ内の異アカウント投稿ペア | 高 | 意味的類似判定が有効で、上限に収まる場合。 |
| 発見候補 | 完全一致を除く投稿を投稿日時順に並べたときの隣接する異アカウント投稿ペア | 低 | 文字列近似候補の後に、上限に収まる場合。 |

同一ペアが両方の候補種別に該当する場合は1件として扱う。候補は投稿時刻差、投稿IDの順で安定して並べる。1回の実行で意味的に確認する候補は最大50組、同時要求は最大3組とする。発見候補は全組合せを作らないための限定的な再現率拡張であり、時系列上離れた言い換えを網羅しない。

### 4.5 LLM判定による最終近似一致の再構成

意味的類似APIが完了結果を返した場合、最終近似一致は以下の規則で再構成する。

| 判定対象 | LLM結果 | 最終近似一致への扱い |
| --- | --- | --- |
| 文字列近似候補 | `match` | 維持する。 |
| 文字列近似候補 | `non_match` | 当該エッジを除外する。 |
| 文字列近似候補 | `abstain`、利用不可、未確認 | 決定的候補として維持する。 |
| 発見候補 | `match` | 当該エッジを追加し、近似一致クラスタを形成又は拡張する。 |
| 発見候補 | `non_match`、`abstain`、利用不可、未確認 | 近似一致へ追加しない。 |

再構成後は、異なるアカウントが2つ以上ある連結成分だけを近似一致クラスタとして表示する。クラスタIDは完全一致を先頭にし、近似一致の類似度、アカウント数、投稿日時で安定して再採番する。画面と証拠パッケージには、意味的確認件数、`match`、`non_match`、棄権・利用不可、LLM追加件数、LLM除外件数を表示する。

### 4.6 クラスタと証拠

各クラスタは以下の情報を表示・出力する。

| 項目 | 内容 |
| --- | --- |
| クラスタID | 表示ごとに`C-001`形式で採番する。 |
| 判定種別 | 完全一致または近似一致。 |
| 最大類似度 | クラスタ内の有効エッジにおける最大の決定的又は意味的スコア。 |
| アカウント数 | 異なるアカウント識別子の件数。 |
| 投稿件数 | クラスタ内の投稿件数。 |
| 証拠投稿 | アカウント識別子、投稿URL、投稿日時、投稿本文。 |
| 意味的確認 | 近似一致の場合に、完了件数、ラベル集計、最大スコア、解決済みモデルを表示する。 |

### UC-03用の時系列コピー候補

利用者が起点投稿IDまたは起点アカウントのどちらか一方を指定した場合、各起点投稿より**後に投稿された**、異なるアカウントの完全一致または閾値以上の近似一致だけを後発コピー候補として抽出する。同時刻の投稿、起点より前の投稿、同一アカウントの投稿は候補に含めない。候補表示には起点投稿、後発候補、判定種別、類似度、起点からの時刻差を含める。これは時刻順と本文類似に基づく候補抽出であり、意味的類似APIの対象ではない。

## 5. 画面仕様

| 領域 | 初期表示 | 操作と結果 |
| --- | --- | --- |
| 注意事項 | 正規取得データのみ・自動通報なし・意味的判定時の送信範囲を表示 | 利用者が前提を確認する。 |
| ファイル入力 | 未選択 | CSV/JSON選択後に形式・件数を検証する。 |
| 判定設定 | 近似一致有効、閾値0.80、URL/メンション無視有効、意味的類似無効 | 設定変更後、検出を実行する。 |
| 意味的類似設定 | 無効 | 有効化時にローカルAPIの設定状態を確認し、利用可能な場合だけ実行する。 |
| 起点指定（UC-03） | 未指定 | 起点投稿IDまたは起点アカウントを一方だけ指定すると、後発コピー候補モードで解析する。このモードでは意味的類似を無効にする。 |
| 結果概要 | 0クラスタ、0投稿 | 通常モードでは意味的確認・LLM追加・LLM除外の集計も表示する。 |
| 結果一覧 | 空状態の説明 | クラスタごとの証拠投稿、意味的確認、投稿URL、Xの通報ヘルプへの外部リンクを表示する。 |
| CSV出力 | 結果0件では無効 | 検出済みクラスタをUTF-8 CSVで端末へ保存する。 |
| 証拠パッケージ出力 | 結果0件では無効 | 判定設定、意味的確認集計、生成日時、候補の根拠・注意事項を含むHTMLを端末へ保存する。 |

## 6. 出力仕様

通常のクラスタ出力は`pakulist-results.csv`としてダウンロードする。列は`clusterId`、`matchType`、`similarity`、`accountCount`、`postCount`、`account`、`url`、`postedAt`、`text`の順とする。1つの証拠投稿を1行に出力する。

UC-03の後発コピー候補モードでは`pakulist-copy-candidates.csv`としてダウンロードする。列は`originId`、`originAccount`、`originUrl`、`originPostedAt`、`candidateId`、`candidateAccount`、`candidateUrl`、`candidatePostedAt`、`timeDifferenceSeconds`、`matchType`、`similarity`、`candidateText`の順とし、1候補を1行に出力する。

HTML証拠パッケージは`pakulist-evidence-package.html`として端末へ保存できる。出力には生成日時、解析モード、近似一致の有無・閾値・URL/メンション除外、意味的類似の有効状態と集計、起点指定（ある場合）、判定種別、類似度、投稿URL、本文、投稿日時、アカウント、UC-03の時刻差を含める。HTML本文は入力投稿をテキストとしてエスケープし、外部リソースを読み込まないCSPを付与する。

## 7. 外部連携とセキュリティ

保存済みX API Search JSONのローカル変換を受け入れるが、アプリはX APIへの接続、認証、資格情報の入力・保存、外部取得を行わない。投稿URLおよびXの通報ヘルプは、利用者が明示的にクリックした場合だけ別タブで開く。

意味的類似判定が無効な場合、Webサーバーは静的ファイル配信だけを行う。意味的類似判定を有効にする場合、`app/server.js`はループバック接続だけから`GET /api/semantic-status`と`POST /api/semantic-judgments`を受け付け、`127.0.0.1:4180`の意味的APIへ中継する。中継本文は32KB以下、タイムアウトは12秒とする。意味的APIはキー、モデル、投稿データを永続化・ログ出力しない。キーはブラウザ、入力ファイル、リポジトリ、ログ、Issue、PRへ保存してはならない。

## 8. 非機能要件

対応ブラウザは最新版のChrome、Edge、Firefox、Safariとする。5,000件以下の入力について、一般的なPC上で利用者の操作を妨げない時間内に決定的結果を表示することを目標とする。近似比較は候補絞り込みにより不要な比較を除外し、Node.js上の固定ベンチマークでは近似一致5,000件を5,000ms以下とする。意味的判定は任意であり、最大50候補・同時3要求・12秒の中継タイムアウトに制限する。解析開始時には処理中状態を表示し、実行中の入力・設定変更を防止する。詳細なブラウザ回帰検証は`doc/specs/detail_design/browser_e2e_testing.md`を参照する。
