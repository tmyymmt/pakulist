# システム仕様: ローカルWebアプリMVP

## 1. 目的と適用範囲

本仕様は、正規な手段で利用者自身が取得したX投稿データを入力として、異なる複数アカウント間の重複投稿を検出し、手動通報のために確認できる証拠リストを生成するローカルWebアプリの振る舞いを定義する。本仕様はOSSベース部分だけに適用し、AIによる意味的類似判定は扱わない。

> 本アプリは重複投稿を**検出・整理**する補助ツールであり、違反の最終判断または通報操作を自動化しない。

## 2. 初期状態

アプリ起動時はサンプルデータを読み込まず、ファイル未選択・結果0件の状態で表示する。画面の近似一致判定は有効、類似度閾値は **0.80**、URL・メンションの無視は有効、投稿本文の大文字小文字・全半角・連続空白の正規化は有効とする。入力済みデータや結果はブラウザを閉じると失われ、サーバーや外部サービスに送信しない。

## 3. 入力仕様

### 3.1 受入形式

ファイル選択でUTF-8の`.csv`または`.json`を1ファイル読み込む。ファイル内容はブラウザ内で解析する。CSVの区切り文字はカンマ、引用符はRFC 4180相当の二重引用符とする。

| 項目 | JSONキー / CSV列名 | 必須 | 型・形式 | 説明 |
| --- | --- | --- | --- | --- |
| 投稿ID | `id` | 必須 | 1文字以上の文字列 | 投稿を一意に識別するID。 |
| アカウント識別子 | `account` | 必須 | 1〜30文字の文字列 | `@`は任意。画面では先頭に`@`を補う。 |
| 投稿URL | `url` | 必須 | `https://`で始まるURL | 証拠として利用者が開く投稿リンク。 |
| 投稿日時 | `postedAt` | 必須 | ISO 8601形式 | タイムゾーンを含む日時。 |
| 投稿本文 | `text` | 必須 | 空白以外を1文字以上含む文字列 | 判定対象となる投稿本文。 |

JSONは上記オブジェクトの配列、または`posts`キーに同配列を持つオブジェクトを受け入れる。投稿IDはファイル内で重複してはならない。入力件数の上限は初期版では5,000件とする。

許可済みのX API v2 Searchレスポンスを保存したJSONも受け入れる。この形式では、`data[].id`、`data[].author_id`、`data[].created_at`、`data[].text`と、`includes.users[]`の`id`・`username`を結合し、上記の標準形式へローカル変換する。`author_id`に対応する`username`がない場合は、誤った投稿URLを生成せず入力エラーとする。変換の詳細は`doc/specs/detail_design/x_api_input_adapter.md`を参照する。

この受け入れは、X APIへの接続、認証、資格情報の入力・保存、外部取得を意味しない。API由来データの取得・利用は、`x_data_acquisition_policy.md`と`external_data_governance.md`の許可・ガバナンス要件を満たす後続フェーズでだけ行う。

### 3.2 入力エラー

拡張子、文字コード、必須項目、URL、日時、投稿ID重複、上限件数のいずれかに不備がある場合、解析・検出を中止する。画面は利用者が修正できるよう、原因と該当行番号または配列番号を表示する。

## 4. 検出仕様

### 4.1 テキスト正規化

比較前に投稿本文をUnicode NFKCへ正規化する。小文字化、改行と連続空白の単一空白化、前後空白の除去を行う。設定が有効な場合、URLと`@`から始まるメンションは除去する。ハッシュタグ、絵文字、句読点は保持する。

### 4.2 完全一致

正規化後の文字列が完全に一致する投稿を候補とする。候補に異なるアカウントが2つ以上含まれる場合、判定種別`完全一致`、類似度`1.00`として検出する。同一アカウント内だけで重複する投稿は結果に表示しない。

### 4.3 近似一致

近似一致が有効な場合、完全一致にならなかった投稿ペアを、正規化済み文字列から作成した単語トークンのJaccard類似度で比較する。類似度が指定閾値以上のペアを同一クラスタに連結する。初期閾値は0.80で、利用者は0.50から1.00まで0.05刻みで変更できる。空トークン同士は一致とみなさず、同一アカウントだけのクラスタは除外する。

この手法は決定的であるが、語順の変更、同義語、意味的な言い換えを正確に検出するものではない。意味的類似判定はOSS版の対象外であり、将来の有料拡張点とする。

### 4.4 UC-03の時系列コピー候補

利用者が起点アカウントを指定した場合、同アカウントのクラスタ内で最も早い投稿を起点投稿とする。起点投稿より**厳密に後**に出た他アカウントの完全一致または、起点投稿との直接Jaccard類似度が閾値以上の近似一致だけを後発コピー候補として表示する。同時刻・先行投稿、起点アカウントがないクラスタは候補に含めない。画面とCSVには起点アカウント、起点投稿ID、起点／候補の役割、時刻差を表示する。候補抽出は法的結論ではない。詳細は`doc/specs/detail_design/copy_candidate_timeline.md`を参照する。

### 4.5 クラスタと証拠

連結した投稿集合を検出クラスタと呼ぶ。各クラスタは以下の情報を表示・出力する。

| 項目 | 内容 |
| --- | --- |
| クラスタID | 表示ごとに`C-001`形式で採番する。 |
| 判定種別 | 完全一致または近似一致。クラスタ内に近似ペアがあれば近似一致とする。 |
| 最大類似度 | クラスタ内のアカウントをまたぐ投稿ペアの最大類似度。 |
| アカウント数 | 異なるアカウント識別子の件数。 |
| 投稿件数 | クラスタ内の投稿件数。 |
| 証拠投稿 | アカウント識別子、投稿URL、投稿日時、投稿本文。UC-03では起点／候補の役割と時刻差も含む。 |

## 5. 画面仕様

| 領域 | 初期表示 | 操作と結果 |
| --- | --- | --- |
| 注意事項 | 正規取得データのみ・ブラウザ内処理・自動通報なしを表示 | 利用者が前提を確認する。 |
| ファイル入力 | 未選択 | CSV/JSON選択後に形式・件数を検証する。 |
| 判定設定 | 近似一致有効、閾値0.80、URL/メンション無視有効 | 設定変更後、検出を実行する。 |
| 結果概要 | 0クラスタ、0投稿 | 入力成功時に件数と検出クラスタ数を表示する。 |
| 結果一覧 | 空状態の説明 | クラスタごとの証拠投稿、投稿URL、Xの通報ヘルプへの外部リンクを表示する。 |
| CSV出力 | 結果0件では無効 | 検出済みクラスタをUTF-8 CSVで端末へ保存する。 |

## 6. 出力CSV仕様

出力は`pakulist-results.csv`としてダウンロードする。列は`clusterId`、`matchType`、`similarity`、`accountCount`、`postCount`、`originAccount`、`originPostId`、`copyRole`、`delaySeconds`、`account`、`url`、`postedAt`、`text`の順とする。1つの証拠投稿を1行に出力する。通常の重複検出ではUC-03固有列を空欄とする。

## 7. 外部連携とセキュリティ

本MVPは外部APIを呼び出さず、入力データを保存・送信しない。保存済みX API Search JSONのローカル変換を受け入れるが、APIトークンや資格情報は扱わない。投稿URLおよびXの通報ヘルプは、利用者が明示的にクリックした場合だけ別タブで開く。Xからの直接データ取得は将来、SNSプロバイダーの差し替え可能なアダプターとして実装する。その際は`x_data_acquisition_policy.md`と`external_data_governance.md`に従い、許可、SNSの規約、開発者条件、レート制限、保持期間を満たすことを必須とする。

## 8. 非機能要件

対応ブラウザは最新版のChrome、Edge、Firefox、Safariとする。5,000件以下の入力について、一般的なPC上で利用者の操作を妨げない時間内に結果を表示することを目標とする。近似比較は候補絞り込みにより不要な比較を除外し、Node.js上の固定ベンチマークでは近似一致5,000件を5,000ms以下とする。性能基準、測定条件、回帰チェック、Worker導入の判断条件は`doc/specs/detail_design/performance_and_responsiveness.md`を参照する。解析開始時には処理中状態を表示し、実行中の入力・設定変更を防止する。件数上限を超えるファイルは受け付けない。ファイル読込、入力エラー、設定変更、検出結果、CSV保存、安全な外部リンクをPlaywright Chromiumで自動E2E検証し、CIで再現する。詳細は`doc/specs/detail_design/browser_e2e_testing.md`を参照する。
