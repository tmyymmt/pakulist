# Issue #39: OrcaRouter意味的類似判定の最小サーバーAPIを試作する 作業計画

## 目的

現行OSS MVPのブラウザ処理と`detection.js`を変更せず、OrcaRouterを呼ぶ有料サービス側の境界を確認するローカル専用サーバーAPIを試作する。APIキー未設定時にも外部通信せず、安全に棄権することを最優先とする。

## 実施範囲

| 領域 | 実施内容 |
| --- | --- |
| プロバイダー | `orcarouter-semantic-provider.js`で、固定モデル・JSON Schema応答・タイムアウト・上流障害の棄権を実装する。 |
| HTTP境界 | `POST /v1/semantic-judgments`と`GET /healthz`を、`127.0.0.1`だけにバインドする最小APIとして実装する。 |
| 資格情報 | `ORCAROUTER_API_KEY`をサーバープロセス環境変数だけから読み、未設定なら通信しない。 |
| テスト | 設定なし、固定モデル、429、応答不正、入力検証、ローカル認証、HTTP状態を自動テストする。 |
| 文書 | API入力・出力、起動手順、環境変数、未対応の認証・保存・課金・X API連携を仕様とREADMEへ記録する。 |

## 非対象

現行ブラウザUIからの呼び出し、`detection.js`への依存追加、実APIキーによる結合試験、実データ送信、利用者認証、事案別権限、永続化、決済、利用枠、X API取得、自動通報は対象外とする。

## 完了条件

1. 標準状態でAPIキー・モデル未設定なら、外部通信なしで503・`abstain`を返す。
2. 固定のプロバイダー接頭辞付きモデルだけを許可し、`orcarouter/auto`を拒否する。
3. APIキー、上流のエラー本文、本文テキスト、完全なプロンプトをログ又はHTTP応答へ出さない。
4. 自動テストと全テストが成功する。
5. 実運用の導入ゲートを満たすまで、ローカル試作APIを公開・有効化しない。
