# ローカルWebアプリMVP 作業計画

## 1. 目的

X上の重複投稿を、利用者が**正規に取得済みの投稿データ**から検出し、アカウント単位の証拠リストとして確認・出力できるローカルWebアプリを提供する。初期版では、完全一致と決定的な近似一致だけをOSS部分として実装する。AIによる意味的類似判定、X APIからの直接取得、投稿・通報操作の自動化は実装しない。

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 入力 | CSVまたはJSONの投稿データをブラウザで読み込む。必須項目は投稿ID、アカウント識別子、投稿URL、投稿日時、本文とする。 |
| 判定 | 空白・URL・メンション・英数字の表記を正規化した完全一致、および決定的なトークン集合類似度による近似一致を行う。 |
| 出力 | 2アカウント以上にまたがる検出クラスタを、投稿証拠とともに画面表示およびCSV出力する。 |
| 通報導線 | 投稿URLと、利用者が明示的に開くXの通報ヘルプページへのリンクを示す。自動通報は行わない。 |
| 保存 | 入力データおよび結果はサーバーへ送信・保存せず、利用者のブラウザ内だけで処理する。 |

## 3. 対象外

AI/LLMによる意味的類似判定、OrcaRouter連携、X API認証・課金プラン選定、SNS上の自動収集、スクリーンショット取得、関係性グラフ、自動通報、恒久DBおよびユーザー認証は本issueの対象外とする。

## 4. 成果物

| 種別 | 成果物 |
| --- | --- |
| 仕様 | システム仕様、概要設計、方式設計、詳細設計、READMEの更新 |
| 実装 | Node.jsのローカル静的配信サーバー、ブラウザUI、判定エンジン、サンプルデータ |
| 品質 | 単体テスト、入力検証、手動ブラウザ確認手順 |
| 運用 | 本ファイルおよびhandoverファイル、作業ブランチ |

## 5. 実施順序

1. 仕様と設計を文書化し、入力形式・初期状態・判定条件を固定する。
2. 判定エンジンと入力検証を実装し、単体テストを追加する。
3. ブラウザUI、CSV出力、外部リンクの明示的な利用者操作を実装する。
4. サンプルデータを用いて自動テストと手動確認を実施する。
5. 仕様書・README・handoverを最終状態に更新してコミットし、作業ブランチをプッシュする。

## 6. 受入条件

- 形式が正しいCSV/JSONを読み込むと、異なる2アカウント以上に共通する投稿クラスタだけが表示される。
- 検出結果にはアカウント識別子、投稿URL、投稿日時、本文、判定種別、類似度が含まれる。
- 近似一致の閾値を利用者が画面上で0.50から1.00の範囲で指定でき、初期値は0.80である。
- 不正な入力には画面上で列・行を特定できるエラーを表示する。
- CSV出力には画面に表示した検出結果と同じ証拠情報が含まれる。
- 自動通報、外部API呼び出し、サーバー側へのデータ保存を行わない。
