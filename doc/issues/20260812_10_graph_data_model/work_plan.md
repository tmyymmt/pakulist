# Issue #7 作業計画: 関係性グラフを見据えたデータモデルと保持境界

## 1. 目的

現行ローカルMVPの非保存原則を維持したまま、将来の関係性可視化・再現性・削除対応に必要な論理スキーマ、保存境界、保持・削除方針、グラフ集計契約を定義する。

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 論理スキーマ | 事案、データソース、アカウント、投稿参照、解析実行、クラスタ、エッジ、根拠を定義する。 |
| データ境界 | ブラウザ一時データ、利用者明示エクスポート、将来サービス保存を区別する。 |
| 保持・削除 | `external_data_governance.md`の30日・90日上限、削除伝播、出力制約を参照して設計する。 |
| 集計契約 | 期間・関係種別・最小根拠数でフィルタするグラフ投影と、エッジ根拠・エクスポートの将来API契約を定義する。 |
| 非対象 | DB、ユーザー認証、外部取得、X API、永続保存、実際のグラフUI、個人・属性推測、法的判断。 |

## 3. 競合回避

担当は `tmyymmt`、作業ブランチは `issue/20260812_10_graph-data-model` とする。変更対象は設計文書、要件の参照、README、本Issue専用の作業記録に限定する。現行の`app/`へ保存・認証・グラフ表示を追加しない。AI・OrcaRouter・事業検証は別Issueに残す。

## 4. 受入条件

- [ ] アカウント、投稿、クラスタ、類似度、時系列、エッジ根拠を含む論理スキーマを定義する。
- [ ] ローカル一時データ、利用者が明示保存するデータ、将来サーバーに保持するデータの境界を定義する。
- [ ] 保持期間、削除、エクスポート、再現性、最小化の方針を定義する。
- [ ] グラフ表示に必要な集計・フィルタと将来API契約を定義する。
- [ ] 現行のローカル入力データを無断で永続化しないことを明記する。
