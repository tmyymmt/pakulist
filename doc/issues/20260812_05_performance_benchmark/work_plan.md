# Issue #6: 近似一致解析の性能基準・計測・最適化

## 対象と制約

現行ローカル Web MVP のブラウザ内処理だけを対象とする。外部データ取得、永続化、LLM 呼び出しは追加しない。計測は Node.js 22.13.0 / Linux x64 で行い、測定条件は `app/scripts/benchmark-detection.mjs` に固定した。

## 実装内容

`clusterApproximate` は従来、異なるアカウントの投稿をすべて組み合わせて Jaccard 類似度を算出していた。今回、正規化済みトークンの逆索引を作成し、少なくとも 1 つのトークンを共有する投稿ペアだけを候補として比較するよう変更した。閾値が 0.50 以上の Jaccard 類似度では、閾値を満たすペアは必ず共有トークンを持つため、候補絞り込みで一致を取りこぼさない。

| シナリオ | 件数 | 最適化前 | 最適化後 | 備考 |
|---|---:|---:|---:|---|
| 完全一致 | 1,000 | 10.77 ms | 14.26 ms | 近似比較を実行しない基準値 |
| 近似一致・非重複 | 1,000 | 1,086.32 ms | 8.30 ms | 比較候補を索引で除外 |
| 完全一致 | 5,000 | 41.34 ms | 67.33 ms | 近似比較を実行しない基準値 |
| 近似一致・非重複 | 5,000 | 27,261.04 ms | 38.32 ms | 比較候補を索引で除外 |

> 単回計測の値であり、端末・ブラウザ・データ分布により変動する。回帰判定には同一環境で複数回測定した結果を用いる。

## 実行方法

```bash
cd app
npm run benchmark
BENCHMARK_ITERATIONS=5 npm run benchmark:json
```

`BENCHMARK_ITERATIONS` は 1 から 20 の整数で指定する。JSON 出力には Node.js バージョン、OS、CPU アーキテクチャ、各シナリオの最小・最大・平均処理時間を含める。
