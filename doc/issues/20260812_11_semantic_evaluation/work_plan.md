# Issue #8: 有料AIの意味的類似判定・OrcaRouter連携・原価を検証する 作業計画

## 目的

現行OSS MVPを変更せず、将来のクローズド有料サービスにおける意味的類似判定について、比較可能な評価基盤、外部AI連携の境界、障害時フォールバック、原価の見積もり方法、実装開始前ゲートを定義する。

## 実施範囲

| 区分 | 実施内容 |
| --- | --- |
| 評価データ | 架空テキストだけを含むラベル付きケースを追加する。 |
| 評価ロジック | TP/FP/TN/FN、適合率、再現率、F1、正解率、偽陽性率、棄権率を計算する純粋関数を追加する。 |
| 原価 | 実測トークン数と運用時に確認する単価を入力とする1判定原価の計算式を追加する。 |
| 設計 | OrcaRouterアダプター、結果スキーマ、障害時の安全な棄権、データ境界、導入ゲートを文書化する。 |
| 非対象 | APIキーの設定、OrcaRouterの実API呼び出し、実モデル精度・実料金の確定、SNS自動取得、スクリーンショット、自動通報、`detection.js`へのLLM依存追加。 |

## 完了条件

1. 評価セットと評価関数がリポジトリにあり、単体テストで確認できること。
2. 原価計算が単価を固定せず、実測使用量を入力として扱うこと。
3. 詳細設計が評価指標、外部連携境界、結果スキーマ、フォールバック、原価、導入ゲートを説明していること。
4. `git diff --check`と`npm --prefix app run test:all`が成功すること。
5. 最新の`main`をrebaseしてからPRを作成し、競合がなければマージすること。

## 依存・保留事項

実連携は利用者提供のOrcaRouter APIキー、サーバー側シークレットストア、承認済みデータ取扱い、利用モデル・単価・月額予算の決定、統合テストを必要とする。これらが未充足の間は、AI判定を有効化しない。
