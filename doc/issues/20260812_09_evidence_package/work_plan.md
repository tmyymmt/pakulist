# Issue #5: 手動通報向け証拠パッケージ

## 目的

検出結果を、利用者が手動で確認・通報判断する際に参照しやすい形へ整理する。アプリは自動通報を行わず、候補判定と利用者による最終確認の境界を明確にする。

## 最小証拠セット

| 項目 | 内容 |
|---|---|
| 生成日時 | 証拠パッケージを端末上で生成した日時（UTCを含む） |
| 判定設定 | 近似一致の有無・閾値、URL/メンション除外、解析モード、起点指定 |
| 候補の根拠 | 判定種別、類似度、UC-03では起点からの時刻差 |
| 投稿証拠 | アカウント、投稿日時、投稿URL、投稿本文。UC-03では起点・後発候補の双方を含む |
| 注意事項 | 候補判定であり、法的結論や最終判断ではないこと。利用者が内容・規約を確認すること |

## 出力形式と安全境界

閲覧・印刷用として`pakulist-evidence-package.html`を端末へ保存する。HTMLは外部リソースを読み込まないCSPを持ち、投稿本文はHTMLとして実行せずテキストとしてエスケープする。投稿URLは利用者の明示的なクリックで開くリンクとして保持する。

スクリーンショットはアプリが取得・保存しない。添付が必要な場合は、利用者が投稿の公開範囲、利用許諾、SNSの規約を確認し、必要最小限のものを自身の端末で取得・保管する。通報フォーム送信、通報操作の自動化、外部API、認証、サーバー側保存は実装しない。

## 検証

単体テストで、必要項目、CSP、投稿本文のエスケープ、`noopener noreferrer`、候補・クラスタ両モード、無効な入力を確認する。E2Eテストで、検出済みの結果からHTML証拠パッケージを保存し、注意事項と安全な投稿本文が出力されることを確認する。
