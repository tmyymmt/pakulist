# Issue #32: X外部データ連携の承認・運用開始条件を確定する 作業計画

## 目的

本番サービスで他アカウントのX投稿を取得・利用する前に、利用目的、書面許可、APIアクセス、予算、資格情報、認証、保持・削除・監査・インシデント対応の責任を確定し、実装開始又は保留を判断する。

## 実施範囲

| 区分 | 実施内容 |
| --- | --- |
| 契約・承認 | XとのDeveloper Policy、Developer Agreement、利用契約、書面許可の要否・取得状況を担当者と確認する。 |
| データ最小化 | 対象アカウント、検索条件、期間、出力範囲、目的コード、削除条件を事案単位で定義する。 |
| 運用設計 | 課金プラン、費用上限、レート制限、停止条件、責任者、削除窓口、インシデント連絡先を決める。 |
| 実装準備 | サーバー側シークレットストア、利用者認証、事案別アクセス制御、保持期限・削除・監査の実装単位を設計する。 |
| Go/No-go | 必須条件が未充足なら、外部取得機能を実装・公開しないことを記録する。 |

## 非対象

スクレイピング、ブラウザ自動操作、継続的監視、複数アプリによるレート制限回避、自動通報、現行OSS MVPへの外部通信・認証・保存の追加は対象外とする。

## 完了条件

1. `x_data_acquisition_policy.md`のDAR-01〜DAR-10と`external_data_governance.md`のGOV-01〜GOV-18に、承認・実装・運用の責任者と証跡を対応付ける。
2. 利用目的、対象範囲、APIアクセス、費用、停止条件、削除・監査を承認又は保留として記録する。
3. 実装を開始できる場合は、認証・シークレット・権限・削除・監査・レート制御のテスト計画を作る。
4. いずれかの必須条件が欠ける場合は、実API取得を開始しない。
