# Issue #10 作業計画: ブラウザ操作・入力エラー・CSV出力を自動E2E検証する

## 1. 目的

現行の単体テストだけでは回帰検証できない、ブラウザ上のファイル選択、入力エラー、設定変更、検出結果、安全な証拠表示、CSV保存をChromiumで自動検証し、GitHub Actionsで再現できるようにする。

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 正常系 | JSON/CSV読込、完全一致表示、同一アカウント除外、URL・メンション無視切替、CSV保存。 |
| 安全性 | 投稿本文をDOMノードとして実行しないこと、外部リンクに`target=_blank`と`noopener`があること、利用者クリック前に別タブを開かないこと。 |
| 異常系 | 不正拡張子、壊れたJSON、CSVヘッダ不足、URL・日時不正、重複ID、5,000件超過。 |
| CI | Node.js 22、Playwright Chromium、単体・性能・E2Eの一括実行。 |
| 非対象 | 実X API、ユーザー認証、保存、外部サイトへのリンククリック、視覚回帰スクリーンショット、Safari/Firefox固有の検証。 |

## 3. 実装方針

1. Playwright Testを開発依存に追加し、ローカルサーバーをテスト中だけ起動する。
2. テストは架空の固定フィクスチャとメモリ上のファイルを用い、実Xデータ・資格情報・ネットワーク呼び出しを含めない。
3. `npm run test:e2e`でブラウザテストを、`npm run test:all`で構文・単体・性能・E2Eを実行する。
4. GitHub ActionsではNode.js 22、`npm ci`、Playwright Chromiumの順に準備し、`test:all`を実行する。

## 4. 競合回避

担当は `tmyymmt`、作業ブランチは `issue/20260812_07_browser-e2e` とする。変更はテスト依存、E2Eテスト、CI、テストフィクスチャ、README、仕様、本Issue専用の作業記録に限定する。検出アルゴリズム、既存UI機能、外部連携、認証、保存の実装には変更を加えない。

## 5. 受入条件

- [ ] 正常なJSON/CSV、設定変更、完全一致表示、CSV保存をE2Eで検証する。
- [ ] 主要な入力エラーと5,000件超過をE2Eで検証する。
- [ ] 同一アカウントだけの重複除外、HTML非実行、クリック前の外部タブ非表示を検証する。
- [ ] `npm run test:e2e`と`npm run test:all`が成功する。
- [ ] GitHub Actionsで同じテストを実行する。
