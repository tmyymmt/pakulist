# Issue #6 作業計画: 最大5,000件の近似一致解析の性能基準・計測・最適化

## 1. 目的

最大5,000件の入力に対する近似一致解析が、比較ごとのトークン化と総当たり比較により長時間化する問題を解決する。再現可能なベンチマーク、性能基準、候補絞り込み、利用者向け処理中状態を実装し、回帰を検知可能にする。

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| ベンチマーク | 完全一致・近似一致の1,000件／5,000件を固定データ特性で測定し、`bench:check`で回帰を検知する。 |
| 最適化 | トークン集合の事前計算、集合サイズ上界、Jaccard接頭辞フィルタによる候補索引を実装する。 |
| UI応答性 | 解析開始前の処理中表示、次フレームへの描画委譲、実行中の入力・設定固定を実装する。 |
| 文書 | 性能基準、測定条件、実測値、将来のWorker導入条件を仕様・READMEへ記録する。 |
| 非対象 | X API、認証、データ保存、AI/LLM意味類似、Web Worker、キャンセルボタン、検索アルゴリズム以外のUI再設計。 |

## 3. 実測と決定

最適化前の近似一致5,000件は85,519.6msだった。トークン事前計算・集合サイズ上界後は3,802.7ms、接頭辞フィルタ後は312.0msとなった。現行の回帰基準は近似一致5,000件を5,000ms以下とする。

## 4. 競合回避

担当は `tmyymmt`、作業ブランチは `issue/20260812_06_detection-performance` とする。変更範囲は検出エンジンの候補索引、ベンチマーク、実行時のUI状態、単体テスト、性能仕様、README、本Issueの作業記録に限定する。外部連携・入力データ形式・認証・保存・AI判定には触れない。

- [ ] 既存の完全一致・近似一致の単体テスト結果を維持する。
- [ ] 解析中の状態を描画し、並行実行・設定変更を防止する。
- [ ] 実測環境・データ特性・限界・Worker導入の判断条件を記録する。
