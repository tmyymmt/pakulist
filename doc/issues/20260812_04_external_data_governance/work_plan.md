# Issue #9 作業計画: 外部データ連携に備えた規約準拠・保持・認証情報管理方針を確定する

## 1. 目的

Issue #2で決定した「X公式APIを使う後続のオンデマンド取得」を安全に実装できるよう、データ最小化、保持、削除、再配布、資格情報、アクセス制御、監査、コスト、レート制限、インシデント対応を要件化する。

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 要件 | API取得X Content、導出データ、サービス利用者データ、秘密情報の分類と取扱いを定義する。 |
| 運用 | 保持・削除、削除要求、再配布、秘密情報ローテーション、監査、予算、レート制限、インシデント対応を定義する。 |
| 連携 | `x_data_acquisition_policy.md`のDAR要件と、#3以降の入力アダプター・将来の取得実装との依存関係を明記する。 |
| 非対象 | X API認証・課金・取得処理、恒久DB、ユーザー認証、画面実装、スクリーンショット、自動通報。 |

## 3. 決定事項

1. 外部データ連携の開始には、Xの必要な書面許可、公式API、データソース承認、運用設計を必須ゲートとする。
2. API取得X Contentは原則30日、導出データと監査ログは原則90日を上限とし、削除・保護化・利用不能化・削除要求により短縮する。
3. API取得X Contentの標準出力はPost ID、URL、アカウント、取得時刻、検出根拠とする。本文等の再配布は条件確認後に限定する。
4. API資格情報はサーバー側の秘密情報としてだけ管理し、クライアント、リポジトリ、ログ、エクスポートへ出力しない。
5. 外部データ連携の実装には、認証、事案単位のアクセス制御、削除・レート・費用・監査の保護策を前提とする。
