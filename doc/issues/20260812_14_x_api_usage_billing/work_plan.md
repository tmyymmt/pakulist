# Issue #35: X API取得の利用枠・従量課金を設計する 作業計画

## 目的

有償版が必要な承認・ガバナンス要件を満たした場合に、X APIによるオンデマンド投稿取得を従量課金又は定額利用枠で提供する。無制限取得、利用者承認なしの超過課金、現行OSS MVPへの課金・外部通信の追加を行わない。

## このPRで完了する設計

| 領域 | 定義する内容 |
| --- | --- |
| 料金方式 | 従量課金と定額利用枠の提供条件、販売単位、超過時の既定動作。 |
| 見積り・予約 | 料金カタログ、残利用枠又は最大請求額、利用者承認、冪等キー、二重請求防止。 |
| 消費・停止 | 80%警告、100%停止、原価・契約上限、429、料金期限切れ、契約不整合。 |
| 精算・監査 | 実消費量の確定、未消費予約の解放、非内容型台帳、調整・返金の責任分界。 |
| 導入ゲート | Xの書面許可・契約、サーバー側シークレット、認証・事案別権限、保持・削除・監査、決済・税の承認。 |

## 実装前に外部判断が必要な事項

Xの有効な課金プラン・エンドポイント・請求単位・取得可能範囲、書面許可、販売単位・価格・税・決済費用・粗利下限、決済・返金・会計・法務の担当責任は、契約・運用主体の確認なしに確定できない。実値を公開リポジトリ、Issue、PR、ブラウザ定数へ記録しない。

## 完了条件

1. `x_api_usage_billing.md`、価格設計、取得ポリシー、ガバナンス、計測計画、評価基準が相互参照する。
2. 従量課金又は定額利用枠以外の提供を許容しない。
3. 見積り・予約・停止・精算・監査・二重請求防止を仕様化する。
4. #32の承認・運用開始ゲートを通過するまで実API取得を有効化しないことを明記する。
