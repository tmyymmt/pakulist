# Issue #11 作業計画: 評価基準を実装・検証の実態に合わせて更新する

## 1. 目的

`doc/specs/evaluation_criteria.md` に記載されている「実装ゼロ」「未着手」などの古い状態を、mainブランチにマージ済みのローカルWeb MVP、テスト、およびブラウザ確認の証跡と整合させる。更新後の評価基準では、現行MVPで達成済みの範囲、未検証の範囲、ならびに後続フェーズの対象外事項を明確に区別する。

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 更新対象 | `doc/specs/evaluation_criteria.md` の状態、確定内容、残タスク |
| 更新対象 | Issue #11の作業計画・引継ぎ記録、およびREADMEのドキュメント一覧 |

## 3. 競合回避

担当は `tmyymmt` とし、作業ブランチは `issue/11-update-evaluation-criteria` とする。変更は評価基準、READMEのドキュメント一覧、ならびに本Issue専用の作業記録に限定する。アプリ実装、既存MVP Issueの記録、外部データ取得の設計には変更を加えない。PRは作業開始時に `[WIP]` として作成し、変更範囲を可視化する。

## 4. 実施手順

1. MVPの実装、単体テスト、ブラウザ確認の既存証跡を確認する。
2. 評価基準の各項目を「実装済み」「一部確定」「未着手」に再分類する。
3. 現行MVPの達成範囲と、Issue #2以降で扱う後続フェーズの課題を分離して記載する。
4. READMEに本Issueの記録フォルダを追加する。
5. Markdownの内容、リンク、作業ツリーを検証する。
