# Issue #2 作業計画: 他アカウントのX投稿を正規に取得・利用する経路を決定する

## 1. 目的

利用者自身のXアーカイブだけでは、異なる複数アカウントの重複投稿を比較する主ユースケースを満たせない。この課題に対し、X公式資料に基づいて、他アカウント投稿を取得・利用するための正規経路、許可ゲート、データ利用原則、段階的導入を決定する。

## 2. 対象範囲

| 区分 | 内容 |
| --- | --- |
| 調査 | X公式のSearch Posts、Rate Limits、Developer Policy、Developer Agreement、Developer Guidelinesを確認する。 |
| 決定 | 採用・不採用とする経路、外部取得機能に着手するためのゲート、最初の実装候補、後続Issueの依存順を定義する。 |
| 仕様 | 取得・利用ポリシー、既存要件・仕様索引・READMEの参照を更新する。 |
| 非対象 | X API認証、課金契約、API呼び出し、SNS上の自動収集、スクレイピング、保存基盤、ユーザー認証、スクリーンショット取得、自動通報。 |

## 3. 決定事項

1. 現行OSS MVPは、正規に取得済みのローカルCSV/JSONだけを扱い、外部取得機能を追加しない。
2. 他アカウント投稿を取得する後続機能は、X公式APIだけを候補とする。スクレイピングとブラウザ自動操作は採用しない。
3. X APIまたはX Contentを用いて重複投稿候補を収集・分析・表示するサービスの提供前に、Xへ利用目的を開示し、Developer Policy上必要な書面許可を得る。
4. 許可取得後の最初の実装候補は、利用者指定の条件に対するRecent Searchのオンデマンド・一回限りの検索とする。Full-Archive Searchと継続監視は後続判断とする。
5. 保持・削除・再配布・認証情報管理はIssue #9、標準入力形式への変換はIssue #3で具体化する。

## 4. 競合回避

担当は `tmyymmt`、作業ブランチは `issue/20260812_03_x-data-acquisition-decision` とする。変更は調査・要件・設計文書、READMEのドキュメント一覧、本Issue専用の作業記録に限定する。API実装、認証、保存、既存アプリ、他Issueの作業記録には変更を加えない。

## 5. 受入条件

- [ ] 自分自身のXアーカイブだけでは主ユースケースを満たせない理由を明記する。
- [ ] 採用候補・不採用経路・判断理由をX公式資料への参照付きで記載する。
- [ ] Developer Policy上の書面許可、開発者アカウント、API資格情報、料金、レート制限、削除・再配布の条件を後続着手ゲートとして定義する。
- [ ] 現行MVPに外部取得・認証・保存・自動通報を追加しないことを明記する。
- [ ] #9、#3、将来の`PostProvider`実装への依存順を示す。
